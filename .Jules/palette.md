## 2025-03-01 - Interactive Element States and Form Accessibility
**Learning:** Animated tooltips built with `group-hover` fail for keyboard users unless explicitly mirrored with `group-focus-visible` classes. Parent interactive wrappers (like anchors or buttons) need strict outline and ring definitions (e.g., `focus-visible:outline-none focus-visible:ring-2` with `rounded-full` for circular icons) to correctly inherit and shape the focus indicators without visual clipping. Additionally, for mobile form components inside nested flex/grid containers, native label clicks frequently fail to focus corresponding inputs unless `id` and `htmlFor` attributes are explicitly paired, bypassing default implicit wrapping expectations.
**Action:** When implementing Tailwind's `group-hover` for interactive components with tooltips or nested visibility states, always add equivalent `group-focus-visible` variants. Consistently pair form `<label>` tags with `<input>` elements using explicit `htmlFor` and `id` linking to ensure cross-device click-to-focus accessibility.
